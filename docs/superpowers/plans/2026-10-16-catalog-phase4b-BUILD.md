## CC ruling: lost-response reconciliation, no migration

Generate one `attemptKey` for each intentional sandwich submit; retain the attempt record (key + submitted normalized name + selected shop + owner scope) for the page session. Pending double clicks and retries of that attempt reuse its key and frozen payload. Send the key in the POST body; add optional UUID validation/pass-through without any persistence or change to the SQL signature. The key correlates client attempts only and provides no server replay guarantee. Do not mint a new key merely because a response was lost, or silently rename/re-submit after a collision. A new intentional submit after editing is a new attempt; late results may only update the matching attempt/scope.

On a transport failure (including missing/unreadable identity response), or `name_taken` from a retry, re-read by selected shop, exact owner scope and exact submitted name (trim as the existing parser does; no fuzzy/case-insensitive fallback). Proposed endpoint: read-only POST `jobs/new-sandwich/reconcile`, body `{ attemptKey, shopId, ownerLocationId, name }`; response `{ matched: false }` or `{ matched: true, menuItemId }`. It has the same session/operational role and shop/creation-scope authorization as the create path, rechecked in `lib/catalog/new-sandwich.ts`; no step-up and no DB mutation. Global null owner remains explicit and requires MoO+. Return only the matched identity after validating visibility; never expose creator IDs or other actors' candidates.

Read the active menu row's existing `created_by` and `created_at` columns, with exact owner predicate (`is null` for global, equality for owned) and exact name; derive creator from the row, never from fail-open audit logs or client claims. Original schema is verified in `supabase/migrations/0103_recipe_entities.sql:71` (`created_at` defaults to `now()`, `created_by` exists); migration 0264 stamps `created_by`. Recheck those files at implementation time. Evaluate age with server time: `0 <= now - created_at <= 10 minutes`. Verify the producing recipe relationship/visibility before opening the destination. Missing, ambiguous, different actor, future/invalid timestamp, older than ten minutes, wrong owner/shop or inaccessible candidate does not reconcile. Return normal `name_taken` when a successful read does not match. If the reconciliation read fails, show an unconfirmed/read-error state and allow re-read; do not fabricate a conflict or automatically create again.

Matched copy: EN **“This sandwich was already created; open it”**; ES **“Este sándwich ya se creó; ábrelo”**. Link using `menuItemPageHref` with the authorized selected shop. Do not claim this proves the exact attempt was applied, nor that current edited fields were saved. An independently created same-name sandwich by the same actor inside the window can satisfy this heuristic. No auto-redirect or second creation is necessary.

Required tests: lost response after committed create reconciles; retry `name_taken` reconciles; different actor returns `name_taken`; age just over ten minutes returns `name_taken`; exact ten-minute boundary, wrong scope/name, inaccessible row, read failure, stale in-flight response and stable key across retry. Freeze clock in unit tests. A future migration phase must design durable request-identity storage, atomic replay and payload-conflict semantics; this phase must not imply that guarantee.
