# Vendor Ordering V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Implementers have NO shell — write files; controller runs tests/commits/migrations. Confirm-before-authoring: READ every referenced live file before writing; the live system wins over this prose.

**Goal:** The order as a first-class lifecycle entity on top of the shipped delivery-intake arc: walker births draft POs → Confirm freezes snapshots → tier-appropriate transmit + Mark-placed with durable transmission records → intake receives against the PO → thin reconcile. Plus per-location SKU overlay (activation + pars), cutoff-driven surfacing, and the vendor/SKU admin config surfaces.

**Spec:** `docs/superpowers/specs/2026-08-06-vendor-ordering-v1-design.md` (decisions D1-D5 + §5b/5c attribution laws). Everything additive; day-one behavior identical until config is touched.

**Shipped foundations (this week — implementers read them):** `lib/ordering.ts` (walker/submit/shrinkage; etWalkDay) · `lib/receiving.ts` + `components/receiving/ReceivingForm.tsx` (intake + pre-fill hierarchy) · `lib/credits.ts` · `lib/counts.ts` anchor tiers · `lib/midshift*` attention kinds (shrinkage = the pattern) · vendors admin + SKU admin (`lib/admin/vendors.ts`, `lib/admin/skus.ts`, their components) · house route/auth/error idioms. Highest migration: 0173 → next 0174.

**Conventions locked here:** PO display code = `{location.code}-{YYYYMMDD}-{first 6 of vendor name, alnum upper}` (uniquified with -2, -3 on collision within the day), rendered in every transmitted sheet/subject/body. PO statuses: `draft|confirmed|placed|invoiced|received|reconciled` (invoiced unused until V2 — present in the check so V2 needs no migration). Audit actions: `po.confirmed`, `po.placed`, `po.received`, `po.reconciled`, `po.draft_created` (walker/cutoff births log once per batch with po ids in metadata).

### Task 1: Migration 0174 — the ordering schema (sonnet)
Create `supabase/migrations/0174_vendor_ordering.sql`, house style (read 0170/0172 for idiom; provenance header citing spec §2; RLS enable + two-statement revokes on every new table):
- `location_sku_settings`: id uuid pk, location_id FK not null, sku_id FK vendor_items not null, active_override boolean null, weekday_par numeric null, weekend_par numeric null, updated_by FK users, updated_at default now(), created_at; `unique (location_id, sku_id)`.
- `purchase_orders`: id, location_id FK not null, vendor_id FK not null, par_pass_event_id FK null, display_code text not null, status text not null default 'draft' check (in the 6), confirmed_snapshot jsonb null, confirmed_by FK null / confirmed_at null, placed_by FK null / placed_at null, placed_note text null, ack jsonb null, cutoff_at_confirm timestamptz null, created_by FK not null, created_at default now(); `unique (display_code)`; index (location_id, created_at desc); index (vendor_id, status).
- `po_lines`: id, po_id FK not null, sku_id FK not null, order_qty numeric not null check >= 0, order_unit_label text null, price_cents_at_order integer null, guide_position_snapshot integer null, note text null, created_at; index (po_id).

- Columns: `vendors.transmission_tier text not null default 'manual' check (auto|assisted|manual)` · `vendors.portal_url text null` · `vendor_items.guide_position integer null` · `vendor_deliveries.purchase_order_id uuid null references purchase_orders(id)` · `vendor_contacts.accepts_text_orders boolean not null default false`.
